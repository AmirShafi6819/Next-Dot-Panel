# Support

How to get help with Next.Panel, depending on what you need.

## Usage questions

For "how do I…?" questions, check first:

1. The [README](README.md) — installation, configuration, troubleshooting.
2. [`docs/`](docs/) — architecture, deployment, API, limitations.
3. Existing [issues and pull requests](https://github.com/AmirShafi6819/Next-Dot-Panel/issues) —
   someone may have asked already.

If that does not answer it, open a
[feature request](https://github.com/AmirShafi6819/Next-Dot-Panel/issues/new?template=feature_request.md)
only when you want a new capability; for pure questions, open an issue with a
clear title and describe what you tried. There is no separate forum or chat —
GitHub issues are the support channel.

## Bugs

File a [bug report](https://github.com/AmirShafi6819/Next-Dot-Panel/issues/new?template=bug_report.md).
Include the version, install method, OS, database, logs with secrets redacted,
and reproduction steps. The more precise the report, the faster it gets fixed.

## Feature requests

File a [feature request](https://github.com/AmirShafi6819/Next-Dot-Panel/issues/new?template=feature_request.md)
describing the problem first and the proposal second. Check
[ROADMAP.md](ROADMAP.md) beforehand — the idea may already be planned.

## Security vulnerabilities

**Do not open a public issue.** Report privately via a GitHub Security
Advisory, as described in [SECURITY.md](SECURITY.md). Never post credentials,
keys, tokens, or unredacted logs anywhere public.

## Contributing

Want to fix or build something? Start with [CONTRIBUTING.md](CONTRIBUTING.md).
Good entry points are issues labelled `good first issue` or `help wanted`
when they exist; otherwise small, well-scoped improvements with tests are
always welcome.
